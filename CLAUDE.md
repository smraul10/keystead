# Keystead

Local-first desktop password manager (KeePass-style). Tauri 2 + React 19 + TypeScript + Vite, pnpm. No cloud sync for now.

## Conventions

- Conventional Commits (`feat`, `fix`, `test`, `refactor`, `docs`, `style`, `chore`, `ci`), imperative mood.
- One change per branch (`feat/...`, `fix/...`, `chore/...`), merged through a GitHub Pull Request after review.
- Tailwind classes are sorted automatically by `prettier-plugin-tailwindcss` (run `pnpm format`).
- No external network requests from the UI: fonts and assets are bundled with the app (Fontsource, no CDNs or Google Fonts). Check a dependency's license before adding it (`pnpm licenses list`).
- UI components are written by hand with Tailwind (no shadcn/ui or component libraries). Prefer native HTML elements (`button`, `input`, `dialog`) for built-in accessibility.
- Buttons: always `Button` (variants `primary`, `secondary` by default, `danger`, `danger-subtle`) or `IconButton` (its required `label` becomes the `aria-label`); never a `<button>` with hand-written classes, except the selectable rows of the sidebar and the item list. Neither accepts `className`, so all buttons look the same: the parent decides width and position (wrap a button in a `<div>` to keep it as wide as its text). `type` is `'button'` unless `'submit'` is asked for.
- Password fields: always `PasswordInput`, with the show/hide eye (and any extra `actions`, like the generator's dice) inside the field. It works with `register()` directly; whether it is revealed is controlled by the parent.
- Icons: Lucide (`lucide-react`, ISC). Import each icon by name (only those are bundled), size it with Tailwind (`size-4`) and let it inherit the text color. Lucide adds `aria-hidden` when the icon has no `aria-label` or `title`, so icons next to text need nothing else; an icon-only button needs its own `aria-label`.
- UI rules: never remove the focus indicator (global `:focus-visible` ring in `index.css`); every animation uses `motion-safe:` / `motion-reduce:`; space with `gap` and `padding` rather than margins; write Tailwind class names in full (never build them from pieces); icon-only content is `aria-hidden` and every control has an accessible name.
- Forms use React Hook Form + Zod: the Zod schema is the single source of the rules and of the type (`z.infer`). Native inputs use `register`; controlled components like `Checkbox` use `Controller`. Each error is linked to its field with `aria-invalid` + `aria-describedby`.
- TypeScript runs in strict mode plus `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`. Avoid `!` (non-null assertion) and `as` casts: check the value and let TypeScript narrow it. For states that cannot happen, throw a clear error instead of asserting.
- Data from outside (localStorage, files, IPC) is read as `unknown` and validated before use. Only preferences go to localStorage, never secrets.
- Tauri commands: each one is listed in `build.rs` (`AppManifest::commands`), which generates its `allow-<command>` permission, and granted one by one in `capabilities/default.json` (least privilege: a command missing from either can't be called). Rust types that cross IPC have a twin in TypeScript (`CommandError` ↔ the Zod union in `src/api/errors.ts`, `VaultStatus` ↔ its Zod enum, the vault's `Item` ↔ `itemSchema` in `src/api/item.ts`): keep them in sync. `CommandError::from(keystead_vault::Error)` has no catch-all arm, so a new vault error must be mapped explicitly. Commands that take a while (anything running Argon2) are `async fn`, so they run outside the main thread and the window keeps responding.

## Project structure

- `src/app/`: the app shell. At launch `App` asks Rust for the vault status (the lock store's `status` is `'checking'` until it answers) and shows `CreateVaultScreen`, `UnlockScreen` or `MainScreen` (sidebar + current section), or `StartupError` if Rust can't answer. Every way into the vault (creating, unlocking, or a reloaded window while Rust holds it unlocked) loads its items from Rust into the items store, then shows `MainScreen`. Locking unmounts the whole vault UI.
- `src/components/`: shared UI components (`Button`, `IconButton`, `CopyButton`, `Checkbox`, `PasswordInput`, and `CardScreen`: the centered card of the screens shown while the vault isn't open).
- `src/hooks/`: shared hooks (`useLocalStorage`).
- `src/api/`: the bridge to Rust. One typed function per Tauri command (`getVaultStatus`...), built on `call()`, which validates every answer with Zod and turns every failure into a `CommandFailedError` holding a typed `CommandError`. `commandErrorOf()` gets that typed error in a `catch`, and `errorMessage()` gives the text the UI shows for each kind (a `switch` TypeScript checks for missing kinds). Commands that answer nothing (Rust's `()`) are validated as `null`. Tests replace Rust with `mockIPC`; `src/test/setup.ts` clears it after each test.
- `src/features/<name>/`: one folder per feature (e.g. `generator`) with its main component, its logic and their tests. UI pieces used only by that feature go in its `components/` folder.
- Each feature exposes its public API through `index.ts`. The rest of the app imports it only from there (`@/features/generator`); ESLint blocks deep imports like `@/features/generator/options`.
- `@/` is an alias for `src/`: use it to import from another folder (`@/components/Button`). Inside a feature, use relative imports (`./options`, `../styles`).
- Tests sit next to the file they test (`options.ts` → `options.test.ts`).
- `src-tauri/`: a Cargo workspace. The root crate (`keystead`) is the Tauri app: `commands.rs` (thin `#[tauri::command]` functions), `state.rs` (`AppState`: the vault path and, while unlocked, the `UnlockedVault` behind a `Mutex`; the logic lives and is tested here), `icon.rs` (downloading a website's icon: the only network code) and `error.rs` (`CommandError`, sent to the UI as `{ "kind": ... }`); `src-tauri/crates/vault/` (`keystead-vault`) is the crypto core: key derivation, encryption and the vault file. It doesn't depend on Tauri or the UI, so it builds and tests in seconds anywhere and stays small enough to review. Its `Item` mirrors the UI's `Item` (`itemSchema` in `src/api/item.ts`, re-exported by `features/items/item.ts`) field by field (serde `rename_all = "camelCase"`), so the JSON crosses to the UI unchanged: keep both in sync. Its lints forbid `unsafe` and warn on `unwrap`, `expect` and `panic` outside tests (a panic could lose data: return errors instead); CI runs clippy with `-D warnings`.
- `src/test/setup.ts`: shared test setup (jest-dom matchers, cleanup, and a minimal `<dialog>` stand-in, because jsdom doesn't implement `showModal()` yet).

## Security architecture (target)

- The master key lives only in Rust memory (zeroized on lock) and never crosses IPC to the webview.
- KDF: Argon2id. Encryption: XChaCha20-Poly1305 (RustCrypto crates). No custom crypto.
- Key derivation (`keystead-vault`, `kdf.rs`): Argon2id v1.3 with RFC 9106's second recommended parameters (64 MiB, 3 passes, 4 lanes; about 0.1 s), a 16-byte salt from the OS's secure random generator, and a 32-byte key in `Zeroizing` (wiped when dropped; Argon2's working memory is wiped too). Each vault stores its own parameters, so they can be raised later. A known-answer test checks the derivation against Node's independent Argon2 implementation: changing the derivation would lock users out of existing vaults.
- Encryption (`keystead-vault`, `cipher.rs`): XChaCha20-Poly1305 with a new random 24-byte nonce on every save and the file header as associated data (not encrypted, but authenticated: changing it, e.g. lowering the KDF params, makes decryption fail). Decryption checks the tag before decrypting and returns a single error, "wrong master password, or the vault file is damaged" (the two can't be told apart). The decrypted bytes are `Zeroizing`. The official test vector of draft-irtf-cfrg-xchacha-03 (A.3.1) is a test.
- Vault file (`.kstd`, `format.rs`): a 58-byte header in clear (magic `KSTD`, format version, Argon2 params, salt, nonce; little endian, layout documented in the code) followed by the encrypted JSON vault and its tag; the header is the associated data. Before deriving the key, opening rejects other magic bytes, other format versions and Argon2 params above 1 GiB, 10 passes or 16 lanes (they are read before the tag can be checked, and absurd values could hang the app). `tests/fixtures/v1.kstd` is a vault saved with format 1 and opened by a test: never regenerate it; a new format version adds its own fixture, and old ones must keep opening. New fields in the JSON are optional (`#[serde(default)]`, like `icon`), so vaults saved before them still open without a new format version. `.gitattributes` marks `*.kstd` as binary.
- Files on disk (`file.rs`): `UnlockedVault::create` / `open` / `save`. An `UnlockedVault` keeps the vault and the derived key (never exposed, wiped when dropped: locking = dropping it), so saving doesn't run Argon2 again. Saves are atomic: write a temporary file in the same folder, `sync_all`, then rename it over the vault (`tempfile`), plus syncing the folder on Unix; a crash leaves the old file or the new one, never half of it. `create` never replaces an existing file.
- Secrets in memory (`keystead-vault`): `Item` and `Vault` derive `Zeroize` + `ZeroizeOnDrop` (every field is wiped when dropped, i.e. on lock), the key is `Zeroizing`, and the JSON is written into a buffer of the exact size (a growing buffer leaves unwiped copies behind; a test checks capacity == length). Types that hold secrets have a hand-written `Debug` that prints `<redacted>` (`Item`'s password and notes, `UnlockedVault`'s key); never derive `Debug` on them. A command that receives the master password wraps its `String` in `Zeroizing` right away. Known limits: the OS may swap memory to disk, serde's parsing scratch space isn't wiped, and neither are the IPC message the master password arrives in nor the JavaScript string it comes from.
- Strict CSP in `tauri.conf.json`: only bundled resources (`'self'`), and the UI can only talk to Rust (`connect-src ipc: http://ipc.localhost`). The one exception is `img-src data:`, for the item icons: PNGs that Rust re-encodes from the site's icon, validated as base64 by `itemSchema` (an image can't run code). Never loosen it for convenience. On desktop, `pnpm tauri dev` does not apply the CSP: test it with `pnpm tauri build --debug --no-bundle`.
- Network (`icon.rs`): the only requests in the app, made by Rust and only when the user asks (`download_icon`). It asks `https://<host>/favicon.ico`: always HTTPS (even if the URL says `http`), never with the username or password a URL may contain, no cookies, 10 s for everything, at most 5 redirects and 512 KiB. Images claiming more than 1024×1024 pixels are refused before decoding; the rest are decoded in Rust (`image`, PNG and ICO only) and encoded again as a PNG of at most 64×64, so the UI never gets the website's file. The crypto core (`keystead-vault`) has no network code. `cargo test -- --ignored` runs a test that downloads a real icon (CI doesn't).
- Least privilege: no unused plugins, commands or capability permissions.
- Locking must leave no vault data in the webview: it unmounts the vault UI and empties the items store at once, without waiting for Rust (pending saves keep their own copy of the list and finish first). In Rust, `lock_vault` drops the `UnlockedVault` (wiping the key and the items), and it always works, even if a command panicked while holding the lock (a poisoned `Mutex`).

## Product decisions

- Layout: three columns, like Bitwarden and 1Password: sidebar, item list (search, "+ New") and item details (copy buttons, Edit).
- Sidebar: All items, Favorites, Trash and Generator, with Settings and Lock at the bottom. Each one is added when it works (no dead buttons).
- Navigation is a state in `MainScreen`, with no router: a desktop app has no URLs.
- Lock: when there is a vault, the app starts locked. The unlock screen replaces the whole window (a centered card, never a popup over the vault, so nothing of the vault stays rendered). A wrong master password shows "Wrong master password" and keeps the text selected. "Lock" at the bottom of the sidebar unmounts the vault UI: the section, selection, search and any unsaved form are discarded. Unlocking asks Rust, which runs Argon2 (the button says "Unlocking…" meanwhile); other errors (a damaged file, the disk...) are shown above the button. Reloading the window keeps the vault unlocked: Rust still holds it, so its items are loaded again.
- Auto-lock: after 10 minutes without mouse or keyboard activity (like 1Password), the vault locks exactly as with "Lock" (`useAutoLock` in `MainScreen`, so it only runs while the vault is open). It compares the clock with the last activity every 5 s instead of trusting one long timer (Windows slows down the timers of a minimized window), and coming back after the limit locks instead of counting as activity. Fixed for now (a Settings section may change it); locking when Windows locks or sleeps may come later.
- Clipboard (next PR): copying goes through Rust (`arboard`), excluded from the Windows clipboard history and cloud, and cleared after 30 seconds, on lock and on exit, but only if it still holds what Keystead copied.
- Strength meter (after that): `zxcvbn-ts` estimates typed passwords (dictionary words, names, dates, keyboard patterns), converted to bits to reuse the generator's levels and badge. Shown when creating the vault and in the item's password field; a Poor or Weak master password asks "Use it anyway?" before creating the vault (like Bitwarden).
- Vault: one vault, `Personal.kstd` in the app's data folder (Tauri `app_data_dir`; on Windows inside `%APPDATA%`). Choosing another location or opening other files may come in phase 6. Every change is saved encrypted right away (like Bitwarden and 1Password), no Save button.
- Saving: after each change the items store sends the whole list (`save_vault`), and Rust replaces the vault's items and rewrites the file, like KeePassXC (the file is a single encrypted block, so saving one item means rewriting it anyway). Saves go one at a time, always with the latest list (`saveQueue.ts`): an older list never reaches the disk after a newer one. Loading and clearing the items never save (saving after clearing would empty the vault). Locking waits for pending saves before Rust closes the vault. If a save fails, a fixed red notice at the top says "Your changes couldn't be saved", why, and offers "Try again"; the changes stay on screen. If sync ever comes, Rust can tell what changed by comparing the lists by `id` and `updatedAt` (deleting forever would then need tombstones), so the UI doesn't need a command per action.
- First launch (no vault file): a "Create your vault" screen, a centered card like the unlock screen, with the master password (at least 12 characters, shown as a hint), its confirmation and a warning that nobody can recover the vault if the master password is forgotten. Creating it makes the app's data folder if needed, never replaces an existing file, and leaves the new vault unlocked (like Bitwarden and KeePassXC). Errors from Rust (e.g. the disk) are shown above the button.
- Only login items for now. An `Item` has `id`, `title`, `username`, `password`, `url`, `notes`, `favorite`, `createdAt`, `updatedAt`, `deletedAt` (`null` unless it is in the trash) and `icon` (the site's icon as a base64 PNG of at most 64×64 pixels, or `null`). Text fields are always strings (`''` when empty, never optional) and dates are ISO 8601 UTC strings (JSON-friendly and sortable as text). The word "item" is used both in the UI and in the code.
- Item icons: the site's icon on a white tile when the item has one, otherwise the title's initial on a color derived from the title. Icons are only downloaded on demand, from the edit form (an "Icon" row with a preview, "Download from website" and "Remove", like KeePassXC; saved with Save, discarded with Cancel): Rust asks only `https://<domain>/favicon.ico`, re-encodes it as a PNG of at most 64×64 pixels, and it is stored encrypted in the item. Never ask a third-party icon server for logos (it would learn which sites the user has accounts on).
- Item form: shown in the details column (not a modal). Only the title is required (an item can be just a note); the URL is free text ("github.com" is fine); the password and notes are never trimmed. "+ New" is hidden in Trash, and an item created from Favorites starts as a favorite. The details panel hides every empty field, the password included.
- Editing: a pencil button at the top right of the details, next to the star (not in Trash: restore first). It opens the same `ItemForm`; saving updates `updatedAt` and goes back to the details, and Cancel discards the changes without asking (an "unsaved changes" warning may come later).
- Trash: deleting moves an item to the trash (`deletedAt`) without asking, because it can be undone. Trashed items only appear in Trash, where they can be restored or deleted forever; deleting forever asks for an inline confirmation with the focus on Cancel. Emptying the whole trash, auto-deleting after 30 days and an "Undo" toast may come later.
- Search filters the list as you type: it looks in the title, username, URL and notes (never in passwords), ignores case and accents, and every word must match.
- Lists show favorites first (marked with a star), then the rest. Each group is sorted by title as a person would sort it (`Intl.Collator`): case and accents are ignored and numbers sort naturally (`Server 2` before `Server 10`).
- Password generator: random characters only for now (passphrases may come later, e.g. for the master password). One reusable `PasswordGenerator` component, used in two places: a standalone "Generator" section (copy the password) and the item form, where a dice button (`Dices` icon) next to the password field opens it in a dialog with a "Use password" button (like Bitwarden and KeePassXC). The dialog is a native modal `<dialog>`: Esc or the X button close it (not a click outside), and "Use password" replaces the field's password without asking and shows it.
- The password regenerates live whenever an option changes; the "Regenerate" button gives a new one with the same options.
- Generator options: lowercase, uppercase, digits, symbols (each toggleable), exclude ambiguous characters (`0 O 1 l I`), require at least one character of each enabled type, adjustable length (default 20, range 8–128).
- The generated password is shown color-coded by character type (letters default, digits and symbols in their own colors), like Bitwarden and 1Password, to tell apart look-alike characters.
- Below the password: "Regenerate" (`RefreshCw`, spins on click) and "Copy" (`Copy`, then `Check`) buttons with icon + text, in two full-width columns (Copy shows "Copied" for 2 s). The password box takes the full width and grows when a long password wraps.
- Generator options live in a collapsible panel, closed by default; the length (slider + number) stays visible outside it. The panel state and the chosen options are remembered between sessions (never the password itself).
- Strength indicator: an icon + the level word, colored by level (no bar). The entropy in bits appears as a tooltip. Levels like KeePassXC: Poor < 40 bits, Weak < 75, Good < 100, Excellent ≥ 100.
- Fonts (OFL-1.1, variable, self-hosted via Fontsource): Inter for the whole UI (`--font-sans`, with optical sizes via `opsz.css`) and JetBrains Mono for passwords (`--font-mono`), chosen because it tells apart look-alike characters (`0 O`, `1 l I`). Ligatures are disabled for any mono font, so characters like `!=` or `->` are never merged in a password.
- Theme: light for now. A theme setting (light / dark / system) comes later (phase 6), using Tailwind `dark:` variants.

## Commands

- `pnpm tauri dev` — run the app
- `pnpm build` — type-check and build the frontend
- `pnpm test:rust` — run the vault crate tests (`cargo test -p keystead-vault`)
- `cargo clippy --workspace --all-targets -- -D warnings` (from `src-tauri/`) — lint all the Rust code like CI does
- `cargo test --workspace` (from `src-tauri/`) — run every Rust test, the app's included
